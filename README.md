# Tcyoon RNG — a 3D "roll and place" tycoon

A single-player browser game. Roll for items (an endless rarity ladder), keep them in a backpack, place them on a
grid to build a production line, level up, rebirth into endless prestige regions and defend your base from waves
and bosses. Everything you see and hear is generated by code: no image or audio files, no backend, no build step.

* Vanilla JavaScript ES modules, [Three.js](https://threejs.org) r170 vendored in `vendor/three/` and pinned through an import map.
* The simulation (`src/sim`, `src/gen`, `src/core`) is pure: it imports no DOM and no Three.js, so it is unit-tested in Node and
  driven by two economy/combat simulators.
* Pixel look: the 3D scene is rendered to a low-resolution render target (nearest-neighbour upscale).
* Saves live in `localStorage` (schema version, migrations, corrupt-save backup, text export/import, in-memory fallback).

## Setup

```bash
npm install
npm run dev          # static server on http://localhost:5173
```

Requires Node 20+ (developed on 22). `npm install` only installs dev tools (ESLint, Playwright); the game itself
has no runtime dependencies. All paths are relative, so the folder also works from any sub-path (GitHub Pages).

| Command | What it does |
|---|---|
| `npm run dev` | serve the game (`scripts/serve.js`, port 5173) |
| `npm run lint` | ESLint over `src`, `tests`, `e2e`, `scripts` |
| `npm test` | unit tests (`node --test "tests/**/*.test.js"`) |
| `npm run test:e2e` | Playwright end-to-end tests (headless Chromium with SwiftShader WebGL; starts its own server on :5199) |
| `npm run test:soak` | 5-minute random-input soak + long-numbers soak (`SOAK_MINUTES=1` for a short run) |
| `npm run sim:economy` | economy simulator (`-- --days 5`, `-- --quick`) |
| `npm run sim:combat` | combat simulator (`-- --quick`, `-- --tiers`, `-- --bosses`) |
| `npm run vendor` | re-copy Three.js from `node_modules` into `vendor/three/` (only needed to change the version) |

If Playwright's browsers are not installed: `npx playwright install chromium`.

## Controls

All keys are remappable in **Settings → Controls** (a key that clashes with another action in the same context is refused).

| Action | Default |
|---|---|
| Roll once / ×10 | `Space` / `T` |
| Open Roll, Backpack, Base, Shop, Rebirth, Combat, Rewards, Settings | `1` … `8` |
| Pause | `P` |
| Cancel / close panel / deselect | `Esc` |
| Rotate placed item / sell selected / pick up | `R` / `X` / `Delete` |
| Pan the camera | `WASD` or arrows, or drag with the left mouse button |
| Orbit / zoom / reset | `Q` `E` or right-drag (or Shift-drag) / `+` `-` or wheel / `Home` |
| Fight: take or release manual control | `M` |
| Fight: move / aim / fire (hold) / dash / nova / shield | `WASD` / mouse position or a tap / `F` / `Shift` / `Q` / `E` |

Mouse: click a backpack item's *Place* button, then click a tile (the ghost shows validity; `R` rotates). Drag a placed item to
move or swap it. Touch: a touch bar (rotate / pick up / sell / cancel) appears while placing or selecting and a virtual joystick appears
in fights; every touch control is at least 44 px.

Accessibility: full keyboard use, high-contrast theme, reduced motion (follows the OS setting by default), text size 0.8–1.6×,
colour-blind-safe rarity colours (Okabe–Ito) that are *always* paired with the rarity name and an icon plus optional border styles,
throttled ARIA live announcements (at most one per 1.5 s; urgent ones bypass), captions for every sound, game speed 0.5–4× and pause.

## How the game works

### Rolling and rarity
Tiers are data (`src/data/tiers.json`): odds are "1 in N" at luck 1 for *tier ≥ t*, value is the production/price multiplier.
Twelve hand-written tiers (Common … Omega); beyond them `gen/tiers.js` extends `log10(odds)` and `log10(value)` with a quadratic
forever, with generated names and icons. Tier numbers go up to 10^15.

* **Draw:** with `u` uniform in (0,1], `tier = highest t with odds_t ≤ luck / u`, so `P(tier ≥ t) = min(1, luck / odds_t)`. Luck is endless, computed in log space.
* **Luck** = `(1 + 0.03·(level−1)) × upgrades × boosters × level-reward luck × prestige/tree effects × generator auras`.
* **Pity (two levels):** after 30 rolls without a "1 in 8" or better result, the next roll is guaranteed one; after 200 rolls it is guaranteed a "1 in 120" or better. The Roll panel shows both bars. Pity scales with luck and can be reduced by an upgrade (floor 10%).
* **Roll price** = `10 · (1 + (L−1)/10)³` at level L (polynomial, so rolling never punishes levelling). One free roll every 120 s (cap 3, upgradable). ×10 unlocks at level 5, ×100 at 15, auto-roll at 3 (one roll per 0.6 s, only when affordable and the backpack has room).
* **Backpack:** 20 slots + `8·n + floor(n^1.4)` for tier *n* (price `400·3.2^n`) + permanent bonuses. A full backpack blocks rolls and says so.
* **Items** have a template (data), tier, optional **variant** (each stat ×0.8–1.3 and a name word), optional **hybrid** (a secondary effect, 40% strength), and mutations (slots = `1 + floor(tier/4)`, each mutation level up to 5). Eight types: dropper, conveyor, multiplier, refiner, seller, upgrader, generator, turret (+ weapons as gear).
* **Sell** value = roll price at the level the item was created × `min(50%, 4%·(1+tier) + 10%·mutations)`. Capped at 50% so "roll then sell" can never print money (proved in `tests/rewards.test.js`).
* **Fuse** 3–10 items of any tiers into one: success chance `30% + 10%·extra + 15%·identical` (max 90%, +5% pity up to +30%); on failure the result is boosted towards mutations.

### Item stats (formulas and soft caps)
`V` = tier value. Stat growth exponents: rate `V^0.25`, value `V^0.75`, throughput cap `V^0.3`, flat add `V^0.9`, damage `V`.
**Multiplier-type stats** (multiplier, refiner, seller bonus, generator aura, luck, xp) use a *soft cap*: `1 + base·(1 + log10(V)/2)²`
(polylogarithmic). Without this, stacking several power-law multipliers made a run grow faster than rebirth could
reset it (BUGS.md #14, found by the economy simulator). Mutation multipliers apply on top of the stat they name.
The mega-tile bonus (base larger than the maximum grid) is `1 + 1.5·(1 − 0.97^mega)` (asymptote 2.5×).

### Placement and production
The base is a grid (starts small; expand it with money, free expansions from levels). Items face one of four directions.
**Flow rule:** droppers emit units in the direction they face; every flow item passes units to the cell it faces. Along the
path each item applies, in this order, *throughput cap → flat add → refine → multiply*, and a seller cashes the units out.
Cells that cannot accept units (generators, turrets, empty cells, the edge, loops) block the flow; the Base panel flags blocked
items with the reason. Generators add an aura to neighbours (luck / xp). Because the layout is a functional graph the
income is solved exactly in one pass and is constant while nothing changes, which is what makes offline progress closed-form.
Presets save and restore a layout; *Auto-place* builds a sensible line.

### Mutations and the refinery
Data-driven (`src/data/mutations.json`): each has a chance, an optional minimum tier, a group (one per group per item), effects and
which item types it applies to. Luck raises the chance (capped). Beyond the list, `gen/mutations.js` generates endless
mutations `g:<stage>` for high tiers. The **Refinery** (money sink): *re-roll* (new mutations with boosted odds, can be worse),
*transfer* (move one mutation between items), *combine* (same mutation on both: level +1, may fail). Cost = roll price × factor × (1 + 0.5·mutations).
Placed *refiner* items also add a refine multiplier to the flow.

### Levels
`xpForLevel(L) = 25 · 1.16^(L−1) · (1 + L/4)`. Rolling and selling give XP. Every level above the hand-written ones follows the
documented generator in `sim/rewards.js` (money in roll prices `0.5 + L/50`, free rolls, backpack slots, luck, expansions, gear slots,
tier-scaled items). Rewards are paid through a ledger, so each level pays **exactly once**, also across reloads. Consumable rewards are divided by your XP
multiplier, so faster levelling never prints money. Jumps of more than 64 levels are resolved in closed form (a 10^300 XP
jump takes milliseconds). Levels are capped at 10^12 (an exactly representable integer; see BUGS.md #29).

### Rebirth and endless prestige
Layer 0 ("Rebirth") needs `1,000,000` run money; layer *k* ≥ 1 uses the lower layer's run total; layers 1 and 2 need 100 and 400, generated layers `threshold = 100·4^(k−1)`.
**Gain** = `floor((R / threshold)^0.5) × (1 + 0.15·total_{k+1}^0.6)`. **Multiplier** = `1 + a·total^b` from lifetime currency
(a decays per layer, b ≈ 0.7: diminishing returns). Each layer has an upgrade tree of 12 nodes (cost `cost·growth^level`, one is an endless sink)
and one rule. Prestiging layer *k* resets money, items, base, shop upgrades and every lower layer's currency, keeps level/XP, claimed
rewards and counts, and advances the **region**: each region has its own generated theme (5 hand-made themes remixed by hue shift, prop
order and sound transposition, forever), name and item/monster flavour. Layers 0–2 are hand-made, layers ≥ 3 are generated from
`treeArchetypes` and the constants in `rebirth.json`, so layer 50,000 exists and uses the same Big-number maths.

### Combat
* **Waves** come every 60 s from level 4 (start-to-start). Enemy HP = `12 · V((w−1)/3) · template hp`; an enemy attacking the base removes `dpsFrac` of its max HP per second. Enemy resistances use five damage types.
* **Defence:** turrets on the grid and equipped weapons (limited gear slots) fire automatically (crit, splash, chain, pierce, slow, burn specials). Weapons are rolled and equipped from the Combat panel.
* **Arena rush** (optional): double the enemies for 2.5× the reward. **Manual control** (`M`): move, aim, fire, dash, nova, shield; the avatar adds +50% damage. The avatar is invulnerable (enemies only attack the base), a deliberate simplification.
* **Bosses** (optional, endless): boss *n* = equivalent wave `8 + 5n`, HP ×30, seeded name, 2 mechanics (+1 every 5 bosses): phase shield, summoner, enrage, shockwave, regeneration, plating, swiftness. Drops: a weapon with the unique mutation `boss:<n>`, money, a free upgrade level.
* **Losing** costs `min(2% of money, 30 s of income)`; items and the save are never touched. The combat is fully deterministic (seeded) and pure; a closed-form forecast and offline wave resolution use the same numbers.

### Stores, rewards and quests
Upgrade shop (roll / gear / luck categories; price = `baseK · rollPrice · growth^level`, endless), timed boosters (same booster extends,
never stacks), backpack tiers, and a **daily rotating shop** seeded by the date (3 items at 80% of their expected roll cost, 2 half-price boosters,
1 half-price upgrade; each offer once per day). 42 quests + 14 achievements + endless generated quests, a daily reward with streaks, playtime rewards,
level-milestone chests and rotating 6-hour chests. Every claim goes through a ledger: nothing can be granted twice. Every purchase checks the balance (`trySpend`): money never goes negative.

### Offline progress
Closed form: `money += income/s × seconds` (split at booster expiries), free rolls accumulate up to the cap, boosters count down, waves are resolved by expected value.
Negative elapsed time (clock moved back) is ignored, elapsed time is clamped to 10 years, and a welcome-back screen summarises what happened (after ≥ 20 s away).
Tested against tick-by-tick simulation (relative error < 1e-6). Known limit: setting the clock *forward* is only bounded by the 10-year clamp.

### Big numbers
`src/core/bignum.js` is a layered number (sign, layer, mantissa, exponent): ordinary doubles up to 1e308, then towers of exponents, saturating at a huge
maximum instead of becoming `Infinity`. `NaN` becomes 0, division by zero is 0, JSON form is `"b<sign>,<layer>,<mantissa>,<exponent>"`.
Display modes: suffixes (K, M, B … aa, ab …), scientific, engineering.

### Randomness
`core/rng.js` is a seeded sfc32 generator with save/restore and `fork`. Everything random (rolls, fuse, mutations, waves, bosses, rotating shop) derives from the
world seed in the save, so a run is reproducible.

## Learning the game: tutorial, tips and difficulty

**First run.** A new save first asks for a pace (Relaxed or Standard; changeable any time in Settings), then starts the guided tutorial. The tutorial runs inside the real game:
16 short steps (`src/data/tutorial.json`, one sentence of at most 20 words each) spotlight the exact button or tile, and each step advances **by itself** when you did the thing
(roll, open the backpack, place the drill, place the stall, watch money rise, buy an upgrade, use a free roll, inspect rarity, read about luck and mutations, place a turret,
watch a practice wave, peek at Rebirth, fuse, sell). The spotlight never blocks input and never steals keyboard focus; the card is reachable with Tab; every step is announced to screen readers;
with reduced motion the ring does not pulse.

* **Skipping asks "Skip the tutorial?"** It lists what you would miss and offers *Keep learning* (default focus, also Esc), *Skip for now* (a Resume chip stays) and *Skip and don't ask again*. The tutorial can be replayed from **Settings → Help and tutorial** at any time.
* **Resumable**: the step is saved with the game. Old saves and experienced players never get a surprise tutorial.
* **Assists** (so a step can always be finished): a top-up of roll money (only if you are short, once per save), one free roll (once), **practice items** when the backpack lacks what a step needs (a drill, a market stall, a turret, three belts for fusing), and a **scripted practice wave** (half the monsters of wave 1, no penalty, no wave progress, no rewards). Practice items are worth $0 and cannot be sold for money, so replaying the tutorial can never farm anything. If a step is stuck for 20 seconds, "Skip this step" appears.
* **Rewards**: a free roll, 2 roll prices of money and 3 roll prices of money + a free roll at three steps; each is paid **exactly once per save** (ledger), also when the tutorial is replayed. Skipping a step pays nothing.

**Tips.** Short one-time hints for new systems (`src/data/tips.json`): backpack full, first mutation, first refiner, first wave, bosses unlocked, first boss, rebirth ready, first rebirth, a new prestige layer, a faster game speed unlocked.
Each shows once (never while the tutorial runs), has an optional button that opens the right panel, can be turned off in Settings, and is listed with its text on **Settings → Help and tutorial → Tips seen** (unseen ones show as ???).

**Difficulty** (`src/data/difficulty.json`, `src/sim/difficulty.js`). Standard is the reference the simulators were calibrated against. **Relaxed** changes exactly these multipliers, nothing else:

| | Standard | Relaxed |
|---|---|---|
| Income from production | ×1 | ×1.15 |
| Time between waves (also offline waves) | 60 s | 90 s |
| Enemy health | ×1 | ×0.85 |
| Money lost when a wave is lost | ×1 | ×0.5 |
| Free roll every | 120 s | 90 s |
| Time to beat a boss | ×1 | ×1.25 |

Both modes are checked by the simulators (`npm run sim:economy -- --difficulty relaxed`, `npm run sim:combat -- --difficulty relaxed`): every check passes in Relaxed too, and the standard run adds a check that Relaxed is easier but not trivial.
Measured honestly: with the bot, Relaxed reaches the third prestige layer 9% sooner (5 h 56 m vs 6 h 30 m); the first rebirths are equal (the bot waits 10 minutes between rebirths in both modes); and the 15% lower enemy health does not change the highest wave a given build beats (the real relief is slower waves, a halved penalty, more boss time and a little more income).

## Game speed

Speed starts at **1×**. Slower speeds (0.5×, 0.75×) are an accessibility option and are never locked. Faster speeds are unlocked by progress; the rules are data in `src/data/speed.json`:
2× at level 10, 4× at level 30, 8× after your first rebirth, and then 16×, 32×, 64× … forever (2^k needs `k − 2` rebirths from 16× on).
**Settings → Game speed** lists locked options as locked with their requirement ("unlocks at level 10"), and a locked speed cannot be chosen (the setting is validated in the simulation, not only in the UI).
Speed scales the simulation only (`core/loop.js`): saves, the real clock and offline progress never see it (offline progress is closed-form from the real elapsed time, so it is identical at every speed, which a unit test checks), and playtime counts real seconds.
Above 4× the fixed step grows (speed/4 × 0.05 s) so the work per frame stays bounded, and combat is still simulated in steps of at most 0.1 s.

## Saves
`localStorage` key `tcyoon-rng:save`: `{ version, savedAt, data }`. Version 2 is current; `MIGRATIONS[1]` upgrades v1 (fixture in `tests/fixtures/save-v1.json`).
An unreadable save is copied to a backup key and the game starts fresh (the Settings panel says so). **Settings → Save data** exports a `TRNG1.<base64>.<hash>` text, imports it (hash verified, corrupt text refused)
and resets. If `localStorage` is unavailable the game plays from memory and warns you to export. All settings are validated on load (`sanitizeSettings`).

## Adding content by data only

No JS changes are needed for any of these (restart or reload the page).

### An item
Append to `src/data/items.json → templates`:
```json
{ "id": "ruby_drill", "type": "dropper", "name": "Ruby Drill", "icon": "💎", "weight": 6, "shape": "drill",
  "minLevel": 2, "base": { "rate": 1.2, "value": 2 } }
```
`type` is one of the keys of `types` in the same file (dropper, conveyor, multiplier, refiner, seller, upgrader, generator, turret); `weight` is its share of rolls within its type;
`base` holds the stats of that type before tier scaling; `shape` picks a procedural model (`src/render/items.js`: drill, pump, belt, … add a new shape there only if you want a new look).

### A mutation
Append to `src/data/mutations.json → mutations`:
```json
{ "id": "frosty", "name": "Frosty", "icon": "❄️", "chance": 0.03, "group": "element", "minTier": 1,
  "applies": ["dropper"], "effects": [{ "stat": "main", "mul": 2 }] }
```
`stat: "main"` is the item type's principal stat; any stat name works. Only one mutation per `group` per item.

### A refiner (placed flow item)
A refiner is an item with `"type": "refiner"` in `items.json` (its `base.refine` is the multiplier bonus). The *Refinery* money-sink operations live in `src/data/refiners.json → ops`
(cost factors and chances); a brand-new operation also needs a handler in `src/sim/refiners.js`.

### A weapon
Append to `src/data/weapons.json → templates`:
```json
{ "id": "ice_lance", "type": "weapon", "name": "Ice Lance", "icon": "🧊", "weight": 6, "shape": "weapon",
  "base": { "dmg": 8, "range": 12, "rof": 1 }, "dtype": "ice", "special": { "kind": "slow", "amount": 0.4 } }
```
`special.kind`: pierce, splash, chain, slow, burn, crit. `dtype` is one of physical, fire, ice, electric, void (void ignores resistance).

### A boss
Bosses are generated endlessly from `src/data/bosses.json` (first wave, step, HP multiplier, drops). Change those numbers to retune every boss, and add a mechanic to
`bosses.json → mechanics` (`id`, `name`, `text`, timing). A brand-new mechanic *id* needs its behaviour in the "boss mechanics" section of `src/sim/combat.js`;
the generated name, drops and unique mutation need no code. Enemies: append to `src/data/enemies.json → templates`.

### A prestige layer
Append to `src/data/rebirth.json → layers` an object like layer 0:
```json
{ "k": 3, "name": "Ascension", "currency": { "name": "Halos", "icon": "😇" }, "kind": "luck", "a": 0.3, "b": 0.7,
  "threshold": 6400, "exponent": 0.5, "rule": { "kind": "startMoney", "per": 5000, "text": "+$5000 starting money" } }
```
A hand-made layer replaces the generated one for that `k` (and optionally a `tree` array of nodes: `id, name, cost, growth, max, effect: { kind, per }`). Without
an entry, layer *k* ≥ 3 is generated automatically. Quests, shop upgrades, level rewards and themes are data files too (`quests.json`, `shop.json`, `rewards.json`, `themes.json`).

## Testing

```bash
npm run lint
npm test                 # unit tests (pure logic: bignum, rng, save, tiers, items, production, rebirth, combat, offline, ...)
npm run test:e2e         # Playwright, ~55 tests (rolling, backpack limit, sell/fuse, placement, level-up, rebirth, rewards once, shop, waves, bosses, offline, persistence, settings, a11y, touch)
npm run test:soak        # 5-minute random-input soak + long-numbers soak
npm run sim:economy -- --quick   # ~45 s: scripted bot plays 1 simulated day with the real sim
npm run sim:economy -- --days 5  # the full proof (~40 s per simulated day)
npm run sim:combat -- --quick
```

**Economy simulator** (`scripts/simulate-economy.js`) plays N simulated days with a scripted bot (rolls limited by the 0.6 s auto-roll budget, places, buys, prestiges) and checks:
no stall, no skippable prestige layer (against spam-roll and never-prestige baselines), rolling pays for itself (A/B against a bot that never rolls), prestige timing in
bounds, all numbers finite. **Combat simulator** (`scripts/simulate-combat.js`) checks that a reasonable tier-*t* build beats waves up to ≈3t and loses before 3t+18, that
bosses sit in their intended band, that numbers stay finite, and that manual play beats waves auto play cannot. Both are run by CI (`--quick`). Results are recorded in `VERIFICATION.md`.

The game exposes `window.__game` (state, debug hooks such as `game.debug.grantMoney`/`advance`, `gpuAudit()`) for tests and the soak; normal play never uses it.

## Deploying to GitHub Pages

`.github/workflows/pages.yml` runs lint + unit tests + both simulators (`--quick`) on every push and pull request; on a push to `main` it also stages
`index.html`, `src/` and `vendor/` into `_site` and deploys it with the official Pages actions. In the repository settings choose
**Settings → Pages → Source: GitHub Actions**. The site works from a sub-path because every URL is relative (`./src/main.js`, the import map points to `./vendor/three/…`).
Any static host works too: copy `index.html`, `src/` and `vendor/`.
Browser requirements: ES modules, import maps and JSON import attributes (`import … with { type: 'json' }`), i.e. current Chrome/Edge/Firefox/Safari releases.
